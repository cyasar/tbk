Öğrenme Hedefleri

  • İnternet ağ altyapısı ile Web (WWW) servisleri arasındaki farkı ayırt etmek.
  • DNS hiyerarşisini ve bir web adresinin IP adresine dönüşüm sürecini açıklamak.
  • TCP ve UDP protokollerinin farklarını ve paket anahtarlama mantığını kavramak.
  • Apache, Nginx, IIS ve Caddy web sunucularının mimarilerini ve kullanım alanlarını karşılaştırmak.
  • Frontend (HTML, CSS, JS, React) ile Backend (PHP, Python, Java, ASP.NET) teknolojilerini rol ve çalışma yeri açısından sınıflandırmak.
  • HTTP istek-yanıt döngüsünü ve durum kodlarını (200, 301, 404, 500) analiz edebilmek.

Temel Kavramlar

İnternet vs. Web (WWW)İnternet küresel ağ donanımı ve yönlendirme altyapısıdır; Web ise bu altyapıda HTTP protokolüyle çalışan bağlantılı sayfalar ve uygulamalar bütünüdür.
IP Adresi & DNSIP cihazların ağdaki sayısal kimliğidir; DNS (Alan Adı Sistemi) ise alan adlarını IP adresine dönüştüren dağıtık bir isim rehberidir.
TCP/IP ve Paket AnahtarlamaVerilerin küçük paketlere ayrılarak ağ üzerinden hedefe güvenli, sıralı ve hata denetimli iletilmesini sağlayan temel iletişim protokolü.
Web Sunucusu (Web Server)HTTP/HTTPS isteklerini (Port 80/443) dinleyen, statik dosyaları sunan veya uygulama motoruna ileten yazılımdır (Nginx, Apache, IIS).
Frontend (İstemci Tarafı)Kullanıcının tarayıcısında çalışan arayüz teknolojileri: HTML (yapı), CSS (görünüm), JavaScript ve React (dinamik davranış).
Backend (Sunucu Tarafı)Sunucu tarafında veritabanı, kimlik doğrulama ve iş mantığını yürüten diller: PHP, Python, Node.js, Java, ASP.NET (C#).
DHCP (Dinamik IP Dağıtımı)Ağa bağlanan cihazlara otomatik olarak IP adresi, ağ geçidi ve DNS bilgilerini kiralayan protokoldür (DORA süreci).
NAT (Ağ Adres Çevirisi)Yerel özel IP'leri tek bir genel IP'ye eşleyerek IPv4 yetersizliğini çözen ve iç ağı gizleyen mekanizmadır.

WWW'NİN DOĞUŞU · 1989

Tim Berners-Lee & WWW Teklifi: 'Vague but exciting...'

CERN nükleer araştırma merkezinde çalışan İngiliz mühendis Tim Berners-Lee, dünyanın farklı yerlerindeki araştırmacıların bilgi ve makaleleri kolayca paylaşabilmesi için hipermetin (hypertext) tabanlı küresel bir bilgi ağı tasarladı. Yöneticisi Mike Sendall, teklif taslağının üzerine meşhur 'Belirsiz ama heyecan verici...' notunu düşerek projeye onay verdi.

Ne değişti? Bilgisayarlar arasındaki internet otoyolunu birbirine bağlı köprü metin belgeleriyle (HTML/HTTP) buluşturan World Wide Web (WWW) vizyonu doğdu.

CERN · The birth of the World Wide Web ↗
WWW'NİN DOĞUŞU · 1990

İlk Web Sunucusu ve İlk Web Sitesi: info.cern.ch

Tim Berners-Lee, Steve Jobs'un NeXT Cube iş istasyonu üzerinde dünyanın ilk web sunucusu yazılımını (CERN httpd) ve ilk web tarayıcısı/editörünü (WorldWideWeb) kodladı. 1991'de 'http://info.cern.ch' adresinde ilk web sayfası yayımlandı. Sunucu kasasının üzerine elle 'Bu makine bir sunucudur, kapatmayın!' yazısı yapıştırılmıştı.

Ne değişti? Dünyanın ilk çalışan web sitesi hayata geçti; HTML sözdizimi, HTTP protokolü ve URL adresleme standardı ilk kez test edildi.

CERN · First Web Server (NeXT Cube) ↗
WEB 1.0 (SALT OKUNUR) · 1993

NCSA Mosaic: Görsel Web Devrimi ve Tarayıcı Çağı

Marc Andreessen ve Eric Bina tarafından Illinois Üniversitesi'nde geliştirilen Mosaic tarayıcısı, metin ve grafikleri aynı sayfa içinde (inline) gösteren ilk kullanıcı dostu tarayıcı oldu. Mosaic, kısa sürede Netscape Navigator'a dönüştü ve kişisel bilgisayar sahiplerinin web ile tanışmasını sağladı.

Ne değişti? Web yalnızca araştırmacıların siyah-beyaz terminal ekranından çıkıp genel halkın ve medyanın ilgisini çeken görsel bir ortama dönüştü.

National Center for Supercomputing Applications · Mosaic ↗
WEB 1.0 (SALT OKUNUR) · 1994

W3C Kuruldu: Web'in Özgür ve Açık Standartları

Tim Berners-Lee, MIT öncülüğünde World Wide Web Consortium'u (W3C) kurdu. CERN ve W3C, web teknolojilerinin (HTML, URL, HTTP) hiçbir kurum veya şirketin mülkiyetinde olmayacağını, tamamen telifsiz, açık ve ücretsiz kalacağını resmen ilan etti.

Ne değişti? Web teknolojilerinin tekelleşmesi önlendi; herkesin eşit erişebildiği küresel ve bağımsız bir bilgi standardı inşa edildi.

W3C · About The World Wide Web Consortium ↗
WEB 1.0 (SALT OKUNUR) · 1995

Web 1.0 (Salt Okunur Web): JavaScript, PHP ve CSS Doğuyor

Brendan Eich, Netscape tarayıcısı için sadece 10 günde JavaScript'i (Mocha/LiveScript) geliştirdi. Rasmus Lerdorf dinamik formlar için PHP'yi yayımladı. Håkon Wium Lie öncülüğünde CSS1 standardı duyuruldu. Web 1.0 dönemi; kullanıcıların içeriği yalnızca okuduğu (Read-Only), statik HTML ve GIF'lerle bezeli sitelerin çağıydı.

Ne değişti? Web tasarım ve programlama katmanları ayrıştı; ancak kullanıcılar henüz içerik üretemeyen pasif birer okuyucuydu.

MDN Web Docs · A Brief History of JavaScript ↗
WEB 2.0 (SOSYAL & AJAX) · 2004

Web 2.0 (Sosyal ve Katılımcı Web) & AJAX Devrimi

Jesse James Garrett 2005'te AJAX (Asynchronous JavaScript and XML) mimarisini tanımladı: Tarayıcılar sayfayı yenilemeden arka planda sunucudan anlık veri çekebilir hale geldi. Web 2.0 ile kullanıcılar yalnızca okuyucu değil; Wikipedia, YouTube, Facebook ve bloglarda bizzat içerik üreticisi (Read-Write Web) oldu.

Ne değişti? Web siteleri tam teşekküllü web uygulamalarına (SaaS) dönüştü; sosyal medya ve kullanıcı üretimli içerik patlaması yaşandı.

Tim O'Reilly · What Is Web 2.0 (2005) ↗
MODERN WEB & SPA · 2010

Mobil Web, HTML5 Standartları ve Node.js

Akıllı telefonların ve mobil internetin yayılmasıyla Flash teknolojisi tarihe karıştı; W3C HTML5 (`<video>`, `<canvas>`, responsive grid) webin kalbi oldu. Ryan Dahl 2009'da Node.js'i duyurarak JavaScript'i tarayıcı tekelinden çıkarıp sunucuda asenkron çalışan güçlü bir backend diline dönüştürdü.

Ne değişti? Mobil ve masaüstü web birleşti; JavaScript hem istemcide (frontend) hem de sunucuda (backend) çalışan evrensel dil haline geldi.

W3C · HTML5 Recommendation & Open Web Platform ↗

React ve SPA (Tek Sayfa Uygulamaları) Çağı

Facebook (Meta), Jordan Walke öncülüğünde geliştirdiği React kütüphanesini açık kaynak olarak yayımladı. Sanal DOM (Virtual DOM) ve bileşen tabanlı (component-driven) mimari sayesinde sayfalar hiçbir zaman yeniden yüklenmeden saniyeler içinde güncellenen zengin arayüzlere (SPA) kavuştu.

Ne değişti? Geleneksel sayfa yenileme döngüsü sona erdi; modern web arayüzleri masaüstü uygulama akıcılığına ve mikroservis entegrasyonlarına ulaştı.

WEB 3.0 & YAPAY ZEKÂ · 2020+

Web 3.0: Semantik Ağ, WebAssembly ve Yapay Zekâ

Tim Berners-Lee'nin ilk günden beri hayal ettiği 'Semantik Web' (makinelerin verinin anlamını kavradığı bağlantılı veri ağı - RDF/Linked Data), WebAssembly (Wasm ile tarayıcıda C++/Rust performansı), merkeziyetsiz veri sahipliği ve Üretken Yapay Zekâ (LLM) servisleriyle birleşti.

Ne değişti? Web; insanlara belge sunan bir depodan, kullanıcı adına düşünen, sorgulayan ve analiz eden akıllı otonom sistemler platformuna evrildi.

Web 1.0, Web 2.0 ve Web 3.0 Karşılaştırması

WEB 1.0 (1989–2004) Salt Okunur Web (Read-Only)

Statik HTML sayfaları, GIF'ler, misafir defterleri. Kullanıcı yalnızca bilgi tüketicisidir; sunucuya içerik besleyemez.

WEB 2.0 (2004–2020) Okur-Yazar Web (Read-Write)

Makinelerin anladığı bağlantılı veriler (Linked Data), WebAssembly (Wasm yüksek performans), merkeziyetsiz protokoller ve Yapay Zekâ ajanları.

Ders İçeriği · İnternet ve ağ teknolojilerinin temelleri

İnternet, bilgisayarları ve aygıtları birbirine bağlayan küresel bir ağlar ağıdır (network of networks). Veriler kesintisiz bir akış olarak değil, paket adı verilen küçük parçalara bölünerek (paket anahtarlama) iletilir.

Her aygıt ağda bir IP adresine (IPv4 veya IPv6) ve fiziksel bir MAC adresine sahiptir. Yönlendiriciler (routers), paketlerin en uygun yol üzerinden hedefe ulaşmasını sağlar.

TCP/IP protokol ailesi iletişimin kurallarını belirler: TCP bağlantı kurarak (3'lü el sıkışma - 3-way handshake) paketlerin eksiksiz ve sıralı gitmesini garanti eder; UDP ise hız öncelikli olup hata kontrolü yapmadan veri gönderir (canlı yayınlar, VoIP, sensör akışları).

Web ve İnternet arasındaki temel farklar: Otoyol ile araçlar

İnternet ile Web (World Wide Web) sıklıkla birbirine karıştırılır ancak aynı şey değildir. İnternet devasa bir fiziksel ve mantıksal otoyol altyapısıdır; Web ise bu otoyolda seyahat eden araç türlerinden yalnızca biridir.

İnternet 1960'larda ARPANET ile başlayan kablolar, uydular, fiber hatlar ve yönlendiricilerden oluşan donanım ağıdır.

Web (WWW), 1989 yılında Tim Berners-Lee tarafından CERN'de geliştirilmiştir. Bu altyapı üzerinde HTTP/HTTPS protokolleriyle köprü metin (hypertext) belgelerinin ve web uygulamalarının paylaşılmasını sağlar.

E-posta (SMTP/IMAP), dosya transferi (FTP), güvenli uzak terminal (SSH), sesli görüşme (VoIP) ve IoT cihaz haberleşmesi (MQTT) doğrudan internet üzerinde çalışır fakat birer Web (HTTP) servisi değildir.

Ağ Yönetim Protokolleri: DHCP, DNS ve NAT Üçlüsü

Bir aygıtın ağa dahil olup web sitelerine erişebilmesi bu üç kritik protokolün işbirliğiyle gerçekleşir:

1. DHCP (Dynamic Host Configuration Protocol - Port 67/68 UDP): Cihaz Wi-Fi veya Ethernet'e bağlandığı anda DORA adımlarıyla çalışır: Discover (Cihaz yayın yapar), Offer (DHCP sunucusu IP önerir), Request (Cihaz kabul eder), Acknowledge (Sunucu onaylayıp IP, alt ağ maskesi, ağ geçidi ve DNS adresini kiralar).

2. NAT (Network Address Translation): IPv4 adres kısıtını (yaklaşık 4.3 milyar adres) çözmek için geliştirilmiştir. Ev veya ofisinizdeki tüm aygıtlar yerel özel IP (Private IP: 192.168.x.x, 10.x.x.x) kullanır. Modem/yönlendirici, dış dünyaya çıkarken bu yerel IP'leri tek bir genel IP'ye (Public IP) ve port numaralarına (PAT - Port Address Translation) dönüştürür. Böylece hem IP tasarrufu yapılır hem de iç ağ dışarıdan doğrudan erişilemez hale gelerek güvenlik sağlanır.

3. DNS (Domain Name System - Port 53 UDP): Cihaz IP aldıktan sonra kullanıcının girdiği 'comu.edu.tr' alan adını sayısal hedef IP'ye çevirerek bağlantının başlamasını sağlar.

DNS nasıl çalışır? Alan adından IP adresine yolculuk

İnsanlar web sitelerini isimleriyle (ör. www.comu.edu.tr) hatırlar; bilgisayarlar ve yönlendiriciler ise yalnızca sayısal IP adresleriyle (ör. 193.255.140.18) iletişim kurabilir.

Tarayıcı adres çubuğuna bir URL yazıldığında DNS (Domain Name System) şu hiyerarşik adımlarla adresi çözer:

1. Tarayıcı ve İşletim Sistemi Önbelleği: Adres daha önce sorgulandıysa doğrudan kullanılır.

2. Yerel DNS Çözümleyici (Resolver): İnternet servis sağlayıcınızın DNS sunucusuna sorulur.

3. Kök Ad Sunucuları (Root DNS - '.'): İsteği ilgili üst düzey etki alanına (TLD) yönlendirir.

4. TLD Ad Sunucuları (.tr, .com, .edu): Ülke veya kurum düzeyindeki yetkili sunucuyu bildirir.

5. Yetkili Ad Sunucusu (Authoritative DNS): Alan adının kesin IP adresini döner.

Elde edilen IP adresi belirli bir süre (TTL - Time to Live) önbelleğe alınır ve TCP bağlantısı başlatılır.

Web sunucu türleri: Nginx, Apache, IIS ve Caddy

Web sunucusu; istemcilerden (tarayıcılar, mobil uygulamalar, ESP32 gibi IoT cihazları) gelen HTTP/HTTPS isteklerini karşılayan ve uygun yanıtı döndüren yazılımdır.

Apache HTTP Server: Açık kaynaklı, modüler yapılı, her dizin için .htaccess yapılandırması sunan en köklü web sunucusudur.

Nginx: Olay güdümlü (event-driven) ve asenkron mimarisi sayesinde binlerce eşzamanlı bağlantıyı çok düşük bellek tüketimiyle karşılar. Modern mimarilerde sıklıkla Ters Vekil (Reverse Proxy) ve Yük Dengeleyici (Load Balancer) olarak konumlandırılır.

Microsoft IIS: Windows Server işletim sistemiyle derin entegrasyon sunar; ASP.NET uygulamaları ve Active Directory tabanlı kurumsal kimlik doğrulama için optimize edilmiştir.

Caddy / Gömülü Sunucular: Otomatik SSL/TLS sertifikası (Let's Encrypt) yönetimi ve mikroservis mimarilerinde dahili HTTP sunucusu (Node.js HTTP, Python Waitress) olarak tercih edilir.

Web yazılım teknolojileri: Frontend (İstemci Tarafı)

Frontend, kullanıcının doğrudan etkileşime girdiği ve kodlarının tarayıcı üzerinde çalıştığı katmandır.

HTML5 (HyperText Markup Language): Web sayfasının iskeletini ve anlamsal yapısını oluşturur (başlıklar, paragraflar, formlar, semantik etiketler).

CSS3 (Cascading Style Sheets): Sayfanın görsel tasarımını, renklerini, yazı tiplerini ve farklı ekran boyutlarına uyumunu (Responsive Tasarım, Flexbox, Grid) belirler.

JavaScript (JS): Tarayıcının yerel programlama dilidir. Sayfaya dinamik davranış kazandırır, kullanıcı tıklamalarını dinler, sayfayı yenilemeden arka planda sunucudan veri çeker (AJAX / Fetch API).

React, Vue, Angular: Modern bileşen tabanlı (component-based) kütüphanelerdir. Büyük web uygulamalarında durum yönetimini (state management) ve sanal DOM (Virtual DOM) ile yüksek performansı sağlar.

Web yazılım teknolojileri: Backend (Sunucu Tarafı)

Backend; sunucu üzerinde çalışan, veritabanı işlemlerini, güvenliği, kullanıcı oturumlarını ve iş mantığını yürüten yazılım katmanıdır.

PHP: Web dünyasının en yaygın dinamik dillerindendir; HTML içine gömülebilmesiyle popülerleşmiştir. WordPress, Drupal ve Laravel çatısı ile modern API'ler ve kurumsal platformlar geliştirilir.

Python (Flask, Django, FastAPI): Temiz ve okunabilir sözdizimi ile hızlı prototipleme, yapay zekâ modelleri entegrasyonu ve IoT veri toplama servislerinde yaygın kullanılır.

Node.js (JavaScript): Sunucu tarafında JavaScript çalıştırmayı sağlar; asenkron I/O mimarisiyle gerçek zamanlı sohbet, telemetri ve soket uygulamalarında çok hızlıdır.

Java (Spring Boot): Güçlü tip güvenliği, kurumsal mimariler, bankacılık ve yüksek ölçekli dağıtık sistemlerin temel standardıdır.

ASP.NET / ASPX (C#): Microsoft tarafından geliştirilen, derlenen, yüksek performanslı ve kurumsal güvenlik standartlarına sahip arka uç geliştirme çerçevesidir.

İstemci-Sunucu mimarisi ve HTTP İstek-Yanıt döngüsü

Web iletişimi İstemci-Sunucu (Client-Server) modeline dayanır. İstemci (tarayıcı veya ESP32) bir HTTP İsteği (Request) gönderir, sunucu bunu işleyip bir HTTP Yanıtı (Response) döndürür.

Temel HTTP Metotları: GET (kaynak okuma), POST (yeni veri gönderme), PUT/PATCH (güncelleme), DELETE (kaynak silme).

HTTP Durum Kodları: 200 OK (başarılı), 301/302 (yönlendirme), 400 Bad Request (hatalı istek), 403 Forbidden (erişim yasak), 404 Not Found (kaynak bulunamadı), 500 Internal Server Error (sunucu hatası), 502 Bad Gateway (ters vekil hatası).

Statik Sayfa İstekleri doğrudan diskten okunurken; dinamik istekler arka uç motorunda (PHP/Python) derlenip veritabanı sorgusuyla üretilir.

Sistem Mimarisi

Bir web sitesini açtığınızda arka planda tek bir bilgisayar değil; DHCP, NAT, DNS, yönlendiriciler, web sunucuları ve backend motorlarından oluşan küresel bir orkestra çalışır. Bileşenlere dokunarak veri akışındaki rolünü keşfedin.

DHCP (Dynamic Host Configuration Protocol - Port 67/68 UDP):

Bir bilgisayar veya telefon ağa bağlandığında manuel IP girmek yerine yönlendiriciden 4 adımda (DORA) otomatik yapılandırma alır.

D 1. Discover (Keşif)

İstemci ağa broadcast (255.255.255.255) haykırır: "Ağda boşta IP dağıtacak bir DHCP sunucusu var mı?"

Bekliyor...
O 2. Offer (Teklif)

Yönlendirici DHCP servisi yanıt döner: "Sana 192.168.1.105 IP'sini ve 192.168.1.1 Gateway'ini öneriyorum."

Bekliyor...
R 3. Request (İstek)

İstemci bildirir: "192.168.1.105 nolu IP teklifini kabul ediyorum, lütfen bana tahsis et."

Bekliyor...
A 4. ACK (Onay & Kira)

DHCP sunucusu onaylar: "IP kiralandı! Alt ağ: 255.255.255.0, DNS: 195.175.39.39, Kira Süresi: 24 saat."

Bekliyor...

Gerçek Dünya Örneği

Laboratuvarda bir ESP32 sıcaklık sensörü Wi-Fi ağına bağlanır. 'comu.edu.tr/api/olcum' adresine HTTP POST ile JSON ölçüm verisi gönderir. Nginx web sunucusu bu isteği alır, Python Flask backend servisine yönlendirir. Backend veriyi MySQL veritabanına kaydeder. Kullanıcı bilgisayarının tarayıcısını açıp sayfaya girdiğinde React arayüzü bu veriyi Fetch API ile çekerek ekranda canlı grafik olarak çizer.

Uygulama

  • ipconfig /renew (Windows) veya dhclient (Linux) ile yönlendiriciden DHCP IP kiralama sürecini deneyimleyin.
  • ipconfig /displaydns ve ipconfig /flushdns ile yerel DNS önbelleğini inceleyip temizleyin.
  • Resolve-DnsName veya dig komutu ile bir alan adının DNS sorgulama aşamalarını ve IP adresini tespit edin.
  • curl -I komutu ile bir web sitesine HTTP başlık sorgusu gönderip web sunucusu türünü (Server header) inceleyin.
  • tracert (veya traceroute) ile hedef sunucuya giden ağ paketlerinin yönlendirici atlamalarını (hop) izleyin.
# PowerShell (Windows)
# 1. DHCP IP Yenileme & DNS Önbellek Temizliği:
ipconfig /release
ipconfig /renew
ipconfig /flushdns

# 2. DNS Çözümleme ve Alan Adı Sorgusu:
Resolve-DnsName www.comu.edu.tr

# 3. Web Sunucusu Başlık (Header) Sorgulama:
curl.exe -I https://www.comu.edu.tr

# 4. Paket Rotalama ve Yönlendirici (Hop) Takibi:
tracert www.comu.edu.tr

# Linux / macOS Terminali
# sudo dhclient -r && sudo dhclient
# dig www.comu.edu.tr +trace
# curl -I https://www.comu.edu.tr
# traceroute www.comu.edu.tr

Kendini Test Et

1. İnternet ile Web (World Wide Web) arasındaki temel fark nedir?

İnternet bilgisayarları birbirine bağlayan küresel ağ ve donanım altyapısıdır; Web ise bu altyapı üzerinde HTTP/HTTPS ile çalışan birbirine bağlı belgeler ve uygulamalar bütünüdür.

2. DHCP ve NAT protokollerinin ağdaki temel görevleri nelerdir?

DHCP ağa katılan cihaza otomatik olarak IP, ağ geçidi ve DNS kiralar (DORA); NAT ise yerel özel IP'leri tek bir genel IP'ye dönüştürerek internete çıkışı ve IPv4 tasarrufunu sağlar.

3. DNS (Domain Name System) sisteminin görevi nedir?

İnsanların hatırlayabileceği alan adlarını (örn. www.comu.edu.tr) yönlendiricilerin ve bilgisayarların haberleşebileceği sayısal IP adreslerine dönüştürmektir.

4. Nginx web sunucusunun Apache'ye göre en belirgin mimari avantajı nedir?

Nginx'in olay güdümlü (event-driven) asenkron mimarisi, çok az bellek tüketimiyle on binlerce eşzamanlı bağlantıyı karşılamasını ve üstün bir Ters Vekil (Reverse Proxy) olmasını sağlar.

5. Frontend (İstemci) ile Backend (Sunucu) teknolojileri arasındaki fark nedir?

Frontend (HTML, CSS, JS, React) kullanıcının tarayıcısında çalışarak arayüzü sunar; Backend (PHP, Python, Java, ASP.NET) sunucuda çalışarak veritabanı, güvenlik ve iş mantığını yönetir.
